# 1:1 重建的实现与验收记录

## 当前边界

当前产物包含真实解包资源、可读专用脚本、静态分析证据、C++17 文件解析器，以及部分独立恢复的 C++ 引擎模块。用户最新明确要求完整源码并否定保留机器码的局部替换版作为交付；`dist/playable` 仅保留为历史测试。独立源码的新入口在 `source_reconstruction/`，包括资源包读取、函数链调度和程序入口控制流；完整游戏仍未完成或链接。

ECL 反编译文本中的 `ins_XXX` 是原版字节码指令；解析出 opcode 和参数不等于已经实现这些指令。把这些文本改名为 `.cpp` 不能产生一个游戏。

自动反编译生成的 C 伪代码仍有未知指针类型、对象布局、调用约定、函数边界与库函数，需根据汇编逐项校正。

## 已有的实现证据

| 模块 | 原版 VA | C++ 状态 |
|---|---|---|
| 随机数模乘核心 | `0x00422cb0` | 48271 与 `2^31-1` 的模运算，保留原始无效种子的低层行为 |
| 随机数状态更新 | `0x004235f0` | 读写一个 32 位状态并返回新状态 |
| 计时器字段复位 | `0x00423f50` | 复位前帧/当前帧/浮点帧，不改 flags |
| 计时器模式位 | `0x00423fe0` | 精确保留无关 flags 位 |
| 计时器设置 | `0x00423f80` | 初始化、整数转 float、上一帧减一及溢出行为 |
| 计时器增加 | `0x004530f0` | 浮点速度倍率、截断和 flags 行为 |
| 计时器前进一帧 | `0x004533b0` | 包含 near-one 特殊路径，整数帧和浮点帧分别更新 |

逐函数机器码在 `analysis/native_verified/`。差分测试 `reports/native_validation.json` 比较返回值与对象字节；它不证明 Windows 锁、线程、全局时钟所有权或完整回放的一致性。

原随机数上层入口 `0x00423ee0` 还有锁与可配置的取模操作，因此目前两个随机数函数只是其核心，不能直接替代整个游戏 RNG 对象。更广的浮点位模式验证结果另见补充报告，不能把正常数值测试外推到所有浮点环境。

## 原始源码结构线索

`analysis/binary/retained_source_layout.json` 从原 EXE 的诊断字符串识别出 81 个源码/头文件路径，并保留原行号与类型字符串。它们是组织逆向工作的线索，不是获得了这些文件源码。可先从以下模块的字符串交叉引用进入：

| 原路径 | 实现任务 |
|---|---|
| `game/mother.cpp`、`game/game.cpp`、`core/main.cpp` | 生命周期、函数链、帧调度、创建/销毁顺序 |
| `game/ecl.cpp`、`script/sptcmd.cpp` | 指令分派、表达式栈、异步脚本、难度条件、全局变量 |
| `game/bullet.cpp`、`game/laser.cpp` | 弹幕生成、变换、删除、激光 |
| `game/enemy.cpp`、`game/stoneenemy.cpp` | 敌机状态、Boss、异变石相关实体 |
| `game/player.cpp`、`game/plyshot.cpp`、`game/bomb*.cpp` | 自机、射击、Bomb、无敌帧 |
| `game/hit.cpp` | 碰撞、擦弹、伤害与判定顺序 |
| `game/item.cpp`、`game/score.cpp`、`game/card.cpp` | 道具、得分与游戏机制 |
| `game/weapon*.cpp` | 红/蓝/绿/黄异变石的各组武器行为 |
| `core/sprtlib.cpp`、`game/background.cpp` | ANM 动画 VM、纹理、混合、STD 背景 |
| `core/pad.cpp`、`game/replay.cpp` | 输入采样、回放读写与随机状态同步 |
| `core/sound.cpp`、`core/zwave.cpp` | 音效时机、音乐流、循环和淡入淡出 |

保留源路径的调用位置可在 `analysis/binary/source_location_xrefs.csv` 查询。文件名本身不能证明某个候选函数边界或完整类布局。

## 分阶段验收

1. **可编译引擎基础**：32 位数据布局、资源加载、函数链、时钟、输入和随机对象。给每个重建函数保存原地址、汇编范围、调用约定及差分报告。
2. **第一关确定性逻辑**：运行原版 ECL，先固定自机和难度，按同一输入/种子比较每帧敌机位置、弹数、弹幕位置/速度及随机调用次数。报告第一处差异，不能只比较最终分数。
3. **完整机制**：逐角色、异变石组合、难度、Boss阶段和额外关卡验证碰撞、生命、资源、伤害、道具与分数。
4. **画面与声音**：同时核对原始渲染分辨率、纹理过滤、坐标舍入、混合顺序、ANM插值、STD背景、音效触发帧与BGM循环。
5. **完整体验**：启动、菜单、配置、输入/手柄、暂停、继续、通关、存档和回放。只有全部场景通过才称为整款游戏 1:1。

增量版已执行部分游戏级验证：真实 Windows 启动、新 DLL 调用计数、主菜单/内置演示画面，以及原版和重建版 `demo2.rpy` 第一关的 1,916 个共享回放帧号、20 个字段稳定采样对照，均未发现所测字段差异。详见 `playable_demo_comparison.json`。这是原引擎执行内置回放的运行回归，尚未独立实现回放解析，也不是全部实体、画面/音频的逐帧锁步证明；第 2–5 项仍需扩大覆盖。
