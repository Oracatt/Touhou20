# LaserInf 管理器源码

已实现 0x58 字节管理器的构造、资源初始化、回调、链表增删、更新/绘制、矩形与圆形消弹、销毁；3,328 项原 CPU 检查覆盖整构造对象及管理器对实体的调用顺序。

`Laser` 的 0x6f8 共同存储与构造/析构已恢复，保留独立 C++ 虚表。`Type3Laser`（0x1d30）的构造、参数复制、初始化、设置标记、删除请求和非空资源释放均已通过原 CPU 整对象对照；其更新/绘制/消弹在原程序中就是零返回短函数，源码中的同等返回有对应汇编证据。包含管理器在内的已验证检查数为 35,072，适用输入哈希见 `pool_validation.json`。

`Type1Laser`（0x1338）的参数、构造、双 ANM 初始化、扩展指令、阶段与旋转、碰撞区域、绘制、五种区域消弹、擦弹和残段分裂已写出。构造/析构、完整初始化、阶段推进、碰撞区域、矩形测量和实际 Type0 子对象分裂已通过原 CPU 对照；更多形状取消和擦弹路径仍在验证。

`Type0Laser`（0x18f8）的构造、三 ANM 初始化、阶段推进、扩展指令、加速/分步转向/反弹、五种区域消弹、真实残段生成与擦弹已写出并编译。构造、三 ANM 初始化、运动、碰撞线段和实际子对象分裂已通过原 CPU 对照；Type0 原版浅拷贝接口尚待处理。

`Type2Laser`（0x1370）的参数、初始化、轨迹链、三种轨迹采样、扩展指令、逐帧更新、曲线几何绘制、区域消弹、分裂和擦弹已编写并编译。三种采样入口新增 49,152 项原 CPU 比较通过；完整实体路径正在验证。ETEX13 的原版固定长度复制已证实超出其实际分配空间，源码明确抛错而不执行堆越界；该非法内存路径没有达到行为等价，见 [TYPE2_ETEX13.md](TYPE2_ETEX13.md)。

`spawn.cpp` 提供四类实体的实际工厂分派，未知类型仍保留原版只递增编号的行为。每份 CPU 报告只适用其记录的源码哈希；管理器测试中的虚调用记录对象只验证管理器契约，不能代替真实实体验证。

该模块不会映射、运行或封装原 EXE。与 Bullet、Bomb 的生产调用已经接通，但这些管理器源码尚不构成完整可玩的独立游戏。证据详见 `pool_validation.json` 的源码哈希、验证范围和排除项。
