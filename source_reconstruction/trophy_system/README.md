# Trophy source recovery

The 0x54-byte TrophyInf, checked PMR integer queue, 128 message records, text resource parsing, encrypted strings, achievement metadata writes, three animation handles, text uploads and 240-frame notification state machine are implemented in C++. `52e210`, `52e730` and `52f900` now connect startup and actual gameplay to this owner.

`cpu_validation.json` records **295,327 passed, zero failed** comparisons. Coverage: 16,384 full-buffer string encodings and decodings; 64 queue lifetimes with 2,048 push/pop operations apiece, comparing offsets, counts, block allocation topology, element contents and PMR allocation/deallocation sizes/order. All 287 text rows in the 41 records of the supplied trophy.txt decode with the original CPU routine. The native oracle is a separate executable and never calls the original program entry. `oracle/build/source_hashes.json` identifies its source inputs.

`pool_validation.json` adds **34,404 passed, zero failed** whole-owner checks: 256 constructor/cache-hit initialization/owned-node destructor cases and 2,048 complete frame calls, including state2 self-deletion, real scheduler behavior, three ANMs, PMR allocation order, GDI text rasterization, deferred uploads and exact texture pixels for both outline flag values. These checks use a recording texture implementation and preload animation files; actual GPU behavior, dynamic resource IO and the complete original ANM resources are outside this test domain. Message file parsing, save mutation and full game integration still need separate end-to-end checks. Compiling this library does not finish the full game. Source validation rejects malformed message indexes/overlong lines rather than allowing the original to write outside allocated records. Valid original assets retain their bytes.

Shared text helper `44add0` uses half the sprite width and the original outline flag polarity; `44b020` is the separate spell-name helper. The notification's original draw callback `49dea0 -> 478bf0` simply returns 1, while its two text completion functions reach the empty `40e5e0`; these verified bodies are not missing implementations.
