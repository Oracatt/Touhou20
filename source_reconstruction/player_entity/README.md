# PlayerInf source reconstruction

The original owner is `0x1485c` bytes, allocated by `4f32b0`, constructed by `4f46a0`, initialized by `4f9520` and published at Context `+4` by `4ffff0`. `owner.hpp` now defines that complete prefix as an actual `runtime::CallbackOwner` subclass with a source-only services pointer suffix. Production never executes original instructions. Scalar collision functions also accept non-owning views for reuse by Bullet, Enemy and Bomb code.

The complete constructor, destructor `4f5320`, initialization, factory and `4feff0` cleanup are recovered. Layout includes the `5e4`-byte ANM, ten plus twelve `12c`-byte Options, `5c`-byte Feedback, and `12598`-byte ShotController containing 256 `124`-byte Shots and two observer-aware lists. Constructors preserve actual unwritten padding, including Player `+14850`; factory allocation is zeroed separately. The original `40c6b0` lifecycle diagnostics do nothing in this release, so no log messages are invented. Teardown unregisters callbacks, retires active shots, handles animation-file preservation and owned SHT storage, then destroys feedback and ANM resources in original order. `shots.cpp` restores `506af0/506ab0` retirement and recycling, including global-context-0 damage lookup behind the current-context guard.

`initialize.cpp` restores `4f9520`, `504bd0`, `4f9470` and the Player/Option/Shot/Feedback context selectors. Production reads actual `plNN.anm` and `plNN.sht`, binds ANM script zero, registers priorities 29/30, initializes fixed-point positions and power settings, and creates the damage owner. `shot_data.cpp` restores the signed SHT offset table at `+5d4`, count16 at `+2`: nonnegative offsets become source-owned pointers, negative sentinels survive. It rejects malformed bounds before mutation; equivalent behavior is claimed for valid resources. The retained-mode `5c60f0` path preserves the original assignment after a new resource read, including the original displaced-pointer ownership quirk. Load failures also preserve the original temporarily published context pointer after factory destruction. These source behaviors are documented rather than silently corrected.

`collision.cpp` restores `460850` position (`+614`), `4ff350` angle to the player, `4ff5e0` focus byte (`+204c`), `4ff800` expanded-collision flag (`+14` bit 4), and `4ff490` current Player `+e8` signed clamp. The angle returns exactly positive pi/2 for a zero x/y difference. Context is at `+14858`; current Player is Context `+24`.

Three complete collision entry sequences are restored:

- `4f8ce0`, axis-aligned overlap using the selected focus extent (`+209c/+20a8`) and a separate 48-by-48 graze region.
- `4f8ff0`, circular overlap using the sum of squared radii. Its two COMISS/JB decisions include unordered IEEE inputs. Focus selects radius `+2094/+2098`; current Player collision percentage mutates through its actual clamp. Expanded collision uses `+2238 * 3.6 * radius`. Graze radius is `max(radius / 2.5, 40)` with the original comparison behavior.
- `4f91d0`, rotated rectangle collision using the recovered `geometry::rectangle_circle` (`457610`) and the original parameter order. It omits the expanded-radius multiplier, uses base radius plus 30 for graze, and returns zero for invulnerable contact. Axis-aligned/circular contact instead returns one while invulnerable.

The production adapter supplies the real nullable boss HUD and the recovered hit source. It also binds Enemy damage's circle/rectangle interfaces. `events.cpp` restores hit `4f86f0` and graze `4f8b90` control flow. Actual adapters use shared Enemy/Bomb notifications, SoundInf, EffectInf, ANM script binding, stream 0 RNG, Item counters and damage rewards. Hit changes overlay mode or player state/timers in the original order. Graze increments Player `+e4` with the original wrapping add/clamp, enqueues type 4 with one RNG draw modulo 4, forces only the color alpha byte, then applies rewards and sound.

`power.cpp` restores complete `4faca0` control flow and `4fb290/4ffd80/4fee50/4f58f0`, with 128-scale fixed-point coordinates, modulo-32 addition and CVTTSS2SI conversion. It preserves the discarded negative-argument getter, maximum-power animations, global versus current focus queries, offset callbacks and option state ordering. Item's power refresh and gameplay's `finish_entity_initialization` bind to this source. `draw_player` restores `4f8af0` using the actual source renderer. The complete Player main frame `4f7430` is now in `frame.cpp`. Overlay `534130/533180/4ff760/4ff630` virtual behavior and shared special-owner getters are supplied by their recovered owning modules. These are not replaced by successful empty bodies.

`firing.cpp` restores `504d40/505d90/504e90`: signed SHT period/phase tests, type-2 existing-shot reuse, all shot initialization fields, option fixed positions, damage bonuses, bounded angle wrapping and RNG order, ANM orientation/scale, DamageRegion callbacks and sound. `506210/505fc0` implement the pool, overflow allocation and wrapping handle; `506480/5060a0/5062f0/506310` implement actual relocated records and Option views. Overflow initially selects global Context 0 even when the requesting controller is Context 1; final initialization then selects the requested view. Shot ANM comes from **Player +24**, distinct from the base animation file at +1c. Production adapters call source ANM, DamageRegion, allocator, RNG and SoundInf. Shot callback resolution binds recovered initialization/update adapters; all initialization, update and hit callbacks are independently compiled C++; the complete Player main frame is connected through the source frame adapter.

`cpu_validation.json` contains **1,029,407 original CPU checks and 2,754 source assertions**, all passed. The functions under comparison retain their original bodies. The new main-frame group uses explicitly recorded external endpoints, as detailed below; the other groups keep their stated native service boundaries. Full constructor and ShotController initialization comparisons retain all original bytes and self-relative list anchors; only the original Player vptr/base bytes are normalized to the independently recovered base. Other CPU cases cover context selectors, fixed-point operations, all power clamps, zero-level complete `4faca0`, scalar accessors and collisions. Scalar collision data includes finite and negative dimensions, zero, infinity, NaN and subnormal values; rotation and atan2 inputs are finite. Nonfinite trig tests terminated the isolated mapped-image process and are excluded. Positive invulnerability avoids executing the original hit graph.

The firing additions include 69,200 CPU comparisons of records, options, pool allocation and complete `504d40` with original nested `505d90` existing-shot reuse.
