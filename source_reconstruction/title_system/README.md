# Title 菜单源码

这里是独立 C++ 游戏使用的标题场景和菜单实现。生产代码不加载或执行原 EXE。`oracle/` 与共享渲染验证程序仅在隔离测试中执行指定哈希的原函数。

已恢复标题生命周期、主菜单、难度和角色选择、宝石配置、音乐室、关卡练习、符卡练习、回放选择、排名登记、录像保存、玩家数据与成就页面。历史 `unrecovered` 名称中的 `gallery` 指符卡练习，`spell` 指排名登记，`stones` 指成就页面；对应包装现在连接到实际源码。

`cpu_validation.json` 保存菜单状态机与外部调用边界对照，`draw_validation.json` 保存共享 Renderer/ANM 验证。边界对照验证状态、定时器、游标及调用顺序；它不代替整个场景、线程文件读取或完整游戏的运行验证。报告中的输入哈希必须与源码匹配后才能用于当前版本。

- 符卡练习：`practice.cpp`、`practice_cards.cpp`、`practice_draw.cpp`，三级选择、解锁筛选、卡片文字、成绩与启动参数。状态机 344,064 项对照通过；绘制/卡片 helper 的 65,536 项范围见 `PRACTICE_DRAW_VALIDATION.md`。
- 玩家数据：`player_data.cpp`、`player_data_draw.cpp`，成绩和符卡记录选择。两个页面 229,376 项对照通过；绘制另行验证。
- 数据解锁：`player_data_keys.cpp` 恢复原按键序列状态，`player_data_unlock.cpp` 恢复原存档修改。后者用 512 组输入比较完整 Snapshot 和 RNG，共 1,024 项通过，合并于 `../progress_state/cpu_validation.json`（该次完整报告 99,312 项通过）。不触及用户存档。
- 音乐室和关卡选择的实际绘制、字体任务、坐标与全对象检查见 `draw_validation.json`。文件读取工作线程和真实 GPU 完整帧不能由文字对照自动推定为已验证。
- 音乐说明的实际归档读取与解析组合见 `MUSIC_PARSER_VALIDATION.md`：4,096 组完整对象状态、285 项真实归档目录及资源字节，共 12,578 项检查通过。原文档缺少结尾 NUL，原解析存在已观察到的堆尾越界读取；报告明确限定堆布局范围，不计作任意未定义输入的等价证明。

自定义回放的原版格式字符串存在已实测的参数错配：某些 slowdown 数值会在原程序中被当作字符串指针，导致访问异常。`replay_draw.cpp` 保留已验证可用输入的显示，对非法指针域给出显式错误；这部分未定义行为不计入完整 1:1 的验证范围。对应原 CPU 探测输入和记录保存在本模块的 Replay 绘制验证材料中。

完整游戏验收仍需要从独立 EXE 启动，验证实际场景切换、全部关卡、输入和同种子回放。菜单库编译或局部对照通过均不表示该验收已经完成。
