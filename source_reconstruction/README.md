# 独立 C++ 游戏源码

本目录包含从目标二进制恢复的游戏源码、生产适配器、模块测试和验证证据。**整套游戏源码已独立编译、链接并实际运行**；源码快照的干净构建记录包含 54 个 MSBuild 项目、464 个实际编译输入。

游戏逻辑从可编辑源码编译，运行时读取原版资源和关卡数据，调用标准系统与图形 API；构建和生产运行不使用原 EXE。恢复目标是行为等价、可编译、可维护的实现，原作者的注释与局部变量名无法从机器码直接取回。

`../build_source_game.ps1` 构建并打包 `../dist/source_game/th20_source.exe`。已修复加载时回调过早启用、敌机释放后访问和激光缓存分配/释放不配对，已有菜单、演示和实际跨入第 3 关的运行记录。**完整游戏流程与整局 1:1 验收仍在进行。** 构建入口见 [SOURCE_BUILD.md](../SOURCE_BUILD.md)，运行证据见 [源码版运行记录](../reports/SOURCE_GAME_RUNTIME.md)；原机器码对照仅存在于独立测试工具中。

## 构建

在仓库根目录执行：

```powershell
.\build_sources.ps1
```

该命令只编译独立模块及源码测试，不需要执行原游戏代码。可选的隔离原函数对照：

```powershell
.\build_sources.ps1 -Validate
```

`-Validate` 构建单独的硬件 oracle 测试工具，其只读映射原 EXE 的选定函数用于差分，不执行原游戏入口；它不是待交付游戏的组成部分。构建结果位于 `build_sources/`。另用 `../build_source_game.ps1` 可构建整套源码 EXE，但成功链接不能替代实际游戏验收。

## 后续覆盖核对与游戏验收

自机逐帧、敌机专用 ECL、死亡处理、暂停、标题菜单、录像和后续场景均已接入源码游戏目标。后续工作是持续核对行为覆盖并完成跨模块和全流程验收；运行中发现的生命周期和内存问题已修复并保留回归证据。原版自身的非法内存访问另行记录，不以静默占位绕过。`link_probe/` 使用真实 WinMain 和源码模块，链接记录与行为验收分别保存。

各模块的 `cpu_validation.json` 等报告说明实际覆盖范围和源码哈希。构造、局部算法、COM 调用序列、真实显卡像素与全游戏逐帧结果属于不同验证层次，不能相互替代。模块持续修改时，旧报告仅对应其中记录的源码版本。

独立模块的局部验证不能推出整款游戏 1:1。完整验收需要在同输入/种子下比较原版与源码版的全部实体状态、碰撞/得分、图像和音频，并覆盖角色、难度、关卡与通关流程。
